# Project: GSK Autonomous Operations (ANO) Production Terraform & AI Pipeline

## Architecture
The GSK Autonomous Operations (ANO) platform transitions global IT, hosting, and network operations (12,000 VMs, 1,500 Applications, 4,000 Apache/Tomcat instances, 600 Relational DBs, 800 Network Switches; ~71.2B daily events / 4.8 TB/day intake) from reactive troubleshooting to predictive, self-healing AI-driven operations on Google Cloud Platform (GCP).

The architecture is structured across 5 core pillars:
1. **Pillar 1: Ingestion & Routing (`terraform/modules/ingestion`)** — Cloud Logging organization/project log sinks (`google_logging_project_sink`) with exclusion filters (`cloudaudit.googleapis.com`, health checks) routing to Pub/Sub topics (`raw_logs`, `gmp_metrics`, `correlated_incidents`) backed by Dead-Letter Queues (`raw_logs_dlq`, `gmp_metrics_dlq`, `correlated_incidents_dlq`) and push/pull subscriptions with exponential backoff.
2. **Pillar 2: Vector Embedding Generation (`terraform/modules/embedding_pipeline` & `src/embedding_worker.py`)** — Cloud Run v2 / Dataflow streaming worker triggered via Eventarc (`google_eventarc_trigger`) that coalesces multi-line stack traces, normalizes dynamic tokens (`<TIMESTAMP>`, `<UUID>`, `<IP_PORT>`, `<HEX_ID>`, `<NUM>`), applies sliding-window chunking (`window_size=5, stride=2`), and invokes Vertex AI Text Embeddings API (`text-embedding-005`, 768 dimensions).
3. **Pillar 3: Analytical & Vector Storage (`terraform/modules/storage_and_vector`)** — BigQuery dataset (`gsk_ano_ops`) hosting 6 `DAY`-partitioned and entity-clustered tables (`raw_logs`, `log_embeddings`, `gmp_metrics`, `topology_edges`, `change_calendar`, `incidents_predictions`), plus stored procedure/job DDL for BigQuery Vector Search index (`CREATE VECTOR INDEX ... OPTIONS(index_type='TREE_AH', distance_type='COSINE')`) and `VECTOR_SEARCH` semantic outlier detection. Architectural comparison and hybrid design with AlloyDB/Cloud SQL `pgvector` (HNSW/ScaNN operational cache) is documented in `docs/ARCHITECTURE_AND_PIPELINE.md`.
4. **Pillar 4: 3-Month Rolling Baselines & Predictive ML (`terraform/modules/bqml_analytics`)** — BigQuery ML routines/jobs implementing:
   - **Capability 1 (Server Unresponsiveness Prediction, 15–30 min lead)**: `LOGISTIC_REG` model (`auto_class_weights=TRUE`) trained on CPU-to-throughput ratio, OS/JVM thread starvation, I/O wait %, disk latency, and socket exhaustion.
   - **Capability 2 (Cross-Domain Correlation & RCA, 30–60 min lead)**: `BOOSTED_TREE_CLASSIFIER` model joining `gmp_metrics` across `topology_edges` (Apache/Tomcat latency, DB lock waits/sessions, network switch OSPF flaps/packet loss weighted by `criticality_weight`) to classify root-cause domain (`APPLICATION`, `DATABASE`, `NETWORK`, `COMPUTE`).
   - **Capability 3 (Dynamic Baselines & Noise Suppression)**: 90-day rolling time-series baseline (`ARIMA_PLUS_XREG` + 168-hour weekly seasonal quantile TVF) joined with ServiceNow/CMDB `change_calendar` (`suppress_alerts = TRUE`) to deterministically suppress alerts during scheduled OS patching and maintenance windows.
5. **Pillar 5: Event-Driven Preemptive Remediation & Alerting (`terraform/modules/alerting_and_remediation` & `src/remediation_webhook.py`)** — Eventarc trigger routing correlated incidents to Cloud Run v2 remediation webhook (`src/remediation_webhook.py`), which verifies `change_calendar` maintenance suppression and per-entity cooldown rate limiting (`cooldown_seconds=900`) before dispatching Cloud Workflows self-healing actions (`DRAIN_AND_RESTART_WORKERS`, `KILL_BLOCKING_DB_SESSIONS`, `REROUTE_OSPF_TRAFFIC`, `SCALE_UP_INSTANCE_GROUP`), paired with Cloud Monitoring notification channels and alert policies (`auto_close=1800s`, `notification_rate_limit=300s`).

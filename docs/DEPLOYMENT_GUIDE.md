# GSK Autonomous Operations (ANO): Production Deployment, Backfill & Model Training Runbook

## 1. Prerequisites & Environment Preparation

### 1.1 Cloud Platform & Quota Requirements
Before deploying the GSK Autonomous Operations (ANO) platform, ensure the target Google Cloud Platform (GCP) environment satisfies the following organizational and quota requirements:
- **GCP Project**: A dedicated production project (e.g., `gsk-ano-prod-01`) linked to an active enterprise billing account.
- **Primary Deployment Region**: `europe-west2` (London) or `us-central1`, co-located with GSK's primary hybrid interconnect and data centre hubs (Stevenage/London).
- **Vertex AI Quota (`aiplatform.googleapis.com`)**:
  - `text-embedding-005` online prediction requests per minute (RPM): **minimum 1,500 RPM** for steady-state streaming (~2,150M log lines/day coalesced into sliding windows); **5,000 RPM recommended** during the initial 90-day historical backfill.
- **BigQuery Slots**: Enterprise edition reservation with baseline 500 slots (autoscaling to 2,000 slots) for concurrent `VECTOR_SEARCH`, `ARIMA_PLUS_XREG` training, and cross-domain graph joins.

### 1.2 Local Bastion / CI-CD Workstation Prerequisites
Ensure the deployment bastion or CI/CD runner has the following binaries installed:
- **Terraform**: `>= 1.5.0` (with `hashicorp/google >= 5.0` and `hashicorp/google-beta >= 5.0` providers)
- **Google Cloud SDK (`gcloud`)**: `>= 460.0.0` (including `bq` and `gsutil` CLI components)
- **Python**: `>= 3.11` (Python `3.13` recommended for running `tests/validate_all.py` and local pipeline utilities)

## 4. Modular Terraform IaC Deployment (`terraform/`)

The infrastructure is organized into a root module (`terraform/`) wiring five production submodules:
1. `modules/ingestion`: Cloud Logging sinks (`exclusions` filtering out `cloudaudit.googleapis.com` and health checks), Pub/Sub topics (`raw_logs`, `gmp_metrics`, `correlated_incidents`), subscriptions, and Dead-Letter Queues (`*_dlq`).
2. `modules/storage_and_vector`: BigQuery dataset `gsk_ano_ops`, all 6 `DAY`-partitioned and entity-clustered tables (`raw_logs`, `log_embeddings`, `gmp_metrics`, `topology_edges`, `change_calendar`, `incidents_predictions`), and the Vector Search Index stored procedures (`sp_create_vector_index`, `sp_semantic_outlier_search`).

4. `modules/embedding_pipeline`: Dedicated service account (`gsk-ano-embed-worker-sa`), least-privilege IAM bindings, Cloud Run v2 service `embedding-worker`, and Eventarc Pub/Sub trigger.
5. `modules/alerting_and_remediation`: Dedicated service account (`gsk-ano-remediation-sa`), Cloud Run v2 service `remediation-webhook`, Eventarc trigger from `correlated_incidents`, Cloud Monitoring notification channels, and rate-limited alert policy (`auto_close = 1800s`, `notification_rate_limit = 300s`).

## 5. Mandatory Initial 90-Day Historical Backfill & CMDB/Calendar Seeding

### 5.1 Engineering Rationale: Why Backfill Must Precede Index & Model Creation
Do **NOT** execute `CREATE VECTOR INDEX` or BQML training queries on an empty greenfield deployment:
1. **BigQuery Vector Index Minimum Row Requirement**: BigQuery's `TREE_AH` and `IVF` indexing algorithms require a minimum of **5,000 vector rows** in `gsk_ano_ops.log_embeddings` to compute k-means cluster centroids and asymmetric hashing codebooks. Running `CREATE VECTOR INDEX` on fewer than 5,000 rows fails with `Invalid value: Cannot create vector index on table with fewer than 5000 rows`.
2. **Seasonal Baseline Cold-Start Prevention**: Capability 3 (`ARIMA_PLUS_XREG` and the 168-hour weekly seasonal quantile TVF) requires **90 days of historical telemetry** across all 168 weekly hourly buckets ($\text{DayOfWeek } [1..7] \times \text{HourOfDay } [0..23]$) to accurately separate normal Monday morning laboratory workload surges from genuine infrastructure anomalies.

### 5.5 Step 5.4: Backfill Historical Vector Embeddings (`log_embeddings`)
Populate `gsk_ano_ops.log_embeddings` with at least 5,000 (typically ~50M+) normalized 768-dimensional vectors using either the Python batch worker or BigQuery native `ML.GENERATE_EMBEDDING`:

```bash
# Option A: Execute BigQuery Native Batch Embedding Generation over 90-day raw_logs
bq query --project_id="${PROJECT_ID}" --use_legacy_sql=false <<'EOF'
INSERT INTO `gsk_ano_ops.log_embeddings`
  (chunk_id, log_id, timestamp, service_name, host_id, domain, severity, chunk_text, embedding, embedding_model, token_count, is_outlier)
SELECT
  GENERATE_UUID() AS chunk_id,
  log_id,
  timestamp,
  service_name,
  host_id,
  domain,
  severity,
  COALESCE(message_template, raw_payload) AS chunk_text,
  ml_generate_embedding_result AS embedding,
  'text-embedding-005' AS embedding_model,
  ARRAY_LENGTH(SPLIT(COALESCE(message_template, raw_payload), ' ')) AS token_count,
  FALSE AS is_outlier
FROM
  ML.GENERATE_EMBEDDING(
    MODEL `gsk_ano_ops.vertex_text_embedding_005_remote`,
    (
      SELECT log_id, timestamp, service_name, host_id, domain, severity, message_template, raw_payload,
             COALESCE(message_template, raw_payload) AS content
      FROM `gsk_ano_ops.raw_logs`
      WHERE timestamp >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 90 DAY)
        AND severity IN ('WARNING', 'ERROR', 'CRITICAL')
    ),
    STRUCT(TRUE AS flatten_json_output, 'RETRIEVAL_DOCUMENT' AS task_type)
  );
EOF
```

Verify that `log_embeddings` contains $\ge 5,000$ rows before proceeding to Section 6:
```bash
bq query --project_id="${PROJECT_ID}" --use_legacy_sql=false \
  "SELECT COUNT(*) AS total_vectors FROM \`${PROJECT_ID}.${DATASET_ID}.log_embeddings\`;"
```

## 6. BigQuery Vector Search Index Creation & Coverage Monitoring

Once `gsk_ano_ops.log_embeddings` is populated, execute the stored procedure provisioned by Terraform (`sp_create_vector_index`) or run the direct DDL to build the `TREE_AH` Cosine Vector Index.

### 6.1 Execute Vector Index DDL
```bash
# Invoke the Terraform-provisioned Stored Procedure
bq query --project_id="${PROJECT_ID}" --use_legacy_sql=false \
  "CALL \`${PROJECT_ID}.${DATASET_ID}.sp_create_vector_index\`();"
```

Or run the explicit DDL directly:
```sql
CREATE VECTOR INDEX IF NOT EXISTS `log_embeddings_vector_idx`
ON `gsk_ano_ops.log_embeddings`(embedding)
STORING(chunk_id, log_id, timestamp, service_name, host_id, domain, severity, chunk_text)
OPTIONS(
  index_type = 'TREE_AH',
  distance_type = 'COSINE',
  tree_ah_options = '{"leaf_node_embedding_count": 1000, "normalization_type": "L2"}'
);
```

### 6.2 Monitor Index Build Progress (`INFORMATION_SCHEMA.VECTOR_INDEXES`)
